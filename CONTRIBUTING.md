# contributing

thanks for looking. this is a bun monorepo with a flutter app inside it, so the
setup is a bit of both.

## setup

```bash
bun install                                    # required, see the sharp note below
cp apps/server/.env.example apps/server/.env
cp apps/mobile/.env.example apps/mobile/.env
bun run db:migrate
```

you need bun 1.3.14 (pinned in `packageManager`) and flutter 3.44.6-stable
(pinned in `.tool-versions`). postgres for the server, xcode for ios, android
sdk for android.

if your change only touches the recorder, the mcap preview or the capture ui,
you can skip postgres and the oauth credentials entirely — put
`NO_AUTH_MODE=true` in `apps/mobile/.env` and the app runs standalone. see the
[quick start](./README.md#just-the-recorder--no-backend-no-account). this is also
the only way to install on a device with a free apple account, since personal
teams can't provision the sign in with apple capability the authed build declares.

**if you touch anything on the auth, upload or startup path, test both modes.**
a `NO_AUTH_MODE` build registers a smaller provider set (see `_noAuthProviders`
in `apps/mobile/lib/main.dart`), so a stray `context.read<AuthProvider>()` on a
shared widget throws there and nowhere else.

run `bun install` rather than letting something else install for you. an
auto-installed `sharp` resolves to a wasm build that crashes part-way through
icon generation in `packages/brand`.

## checks

these have to be clean before a pr is reviewable.

```bash
bun run check            # oxlint + oxfmt via ultracite
bun run check-types      # tsc across the workspace
bun run brand:verify     # structural checks on the theme and identifiers
bun test packages/brand/ # brand engine unit tests

cd apps/mobile
flutter analyze
flutter test
```

`bun run fix` autofixes most lint and format issues.

## the two rules that trip people up

**no design value is a literal in a widget.** colours come from
`context.colors`, radii from `AppRadii`, sizes and weights from
`context.textTheme` or `AppType`, gaps from `AppSpacing`. never `Color(0xFF…)`,
`BorderRadius.circular(12)`, `fontSize: 14` or `SizedBox(height: 12)`.
`Colors.transparent` is the only exception. all four resolve from
`packages/brand/brand.json`, so a literal is a widget that silently opts out of
the theme every other widget follows. `bun run brand:verify` fails on one.

**native code ships as a triad.** contract, impl, method-channel handler, on
both ios and android. the handler is the only file that imports flutter. details
in [`apps/mobile/CLAUDE.md`](./apps/mobile/CLAUDE.md).

typescript standards are in [`AGENTS.md`](./AGENTS.md). worth a skim before your
first pr, it covers the stuff the linter can't catch.

## commits

conventional commits, matching what's already in the log.

```
feat(brand): wire type and spacing into the theme
fix: accept non-string metadata values on asset create
docs(stera_recorder): prepare package for pub
chore(android): raise gradle toolchain for plugin upgrades
```

scope is optional. keep the subject under ~72 chars.

## prs

- one thing per pr. a refactor and a feature in the same diff is two prs
- say what changed and why. if there's a screenshot worth having, include it
- no commented-out code. git is the archive
- if you touched anything under `packages/brand`, say what `bun run brand:preview`
  looks like after your change
- new secrets go in the matching `.env.example` with a placeholder, never a real
  value

## what not to send

- a rebrand. `packages/brand` exists so you can fork and rebrand without a pr.
  changes to the *engine* are welcome, changes that hardcode a different brand
  are not
- generated files. anything with a `GENERATED BY packages/brand/apply.ts` header
  is hash-tracked and editing it makes the next run refuse to start
- `packages/brand/preview.html`. it's generated and gitignored

## reporting a bug

open an issue with the template. for anything security related, do not open an
issue, email contact@fpvlabs.ai.
